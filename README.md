# BytePet

바탕화면에 떠 있는 픽셀 개발자 펫. 현재 구현 범위는 **F01: 투명한 항상 위 창에서 ByteCat 대기 애니메이션 재생**, **F02: 드래그 이동·위치 복원**, **F03: 투명 영역 클릭 투과**, **F04: 유틸리티 패널 열기·닫기**다.

## 실행

Node.js 22.12.0 이상과 npm이 필요하다. 최초 검증 대상은 macOS다.

```sh
npm install
npm start
```

화면 우측 하단에 96×96px 고양이가 나타나 숨을 쉬고, 눈을 깜빡이고, 꼬리를 흔든다. 창은 128×128px이며 배경과 프레임이 투명하다. 별도 서버나 외부 네트워크 연결 없이 로컬 파일을 읽는다.

고양이의 보이는 픽셀을 마우스 왼쪽 버튼으로 잡아 드래그하면 위치를 옮길 수 있다. 클릭 중 작은 손떨림은 이동으로 처리하지 않는다. 마지막 위치는 자동 저장되며 앱을 다시 실행하면 복원된다. 모니터 연결이나 해상도가 바뀌면 현재 화면의 작업 영역 안으로 위치를 보정한다.

창의 투명 여백과 고양이 윤곽 안팎의 완전히 투명한 픽셀에서는 뒤쪽 앱을 클릭할 수 있다. 클릭 영역은 애니메이션에 맞춰 갱신된다. 이미 드래그를 시작했거나 우클릭 메뉴가 열린 동안은 펫이 입력을 유지한다.

고양이를 클릭하면 옆에 유틸리티 패널이 열리고 작업 메모 입력란으로 포커스가 이동한다. 고양이를 다시 클릭하거나 패널의 닫기 버튼·Esc를 누르면 닫힌다. 키보드로 고양이에 포커스를 둔 경우 Enter·Space로도 열고 닫을 수 있다. 드래그하거나 투명한 픽셀을 누르면 패널은 열리지 않는다.

패널은 펫과 함께 이동하고 화면 가장자리에서는 빈 공간에 맞춰 배치된다. 다른 앱을 선택해도 자동으로 닫히지는 않는다. 메모는 패널을 닫고 다시 열어도 유지되지만 디스크에 저장되지 않으며 앱 종료 시 지워진다. JWT 해독·JSON 정리·포트 확인 버튼은 후속 기능으로, 현재는 비활성 상태다.

위치는 Electron의 사용자 데이터 폴더(`app.getPath('userData')`) 아래 `pet-position.json`에 저장된다. 저장 파일이 없거나 손상되면 기본 위치에서 시작한다. 저장에 실패해도 펫은 계속 동작하며 실행 터미널에 오류를 기록한다.

종료하려면 고양이를 우클릭해 **BytePet 종료**를 선택하거나 앱 메뉴에서 종료한다. 시스템의 동작 줄이기 설정을 사용하면 고양이는 정지 상태로 표시된다.

다음 작업은 텍스트 먹이 입력(F05)의 드롭·붙여넣기 처리와 입력 검증이다. 이 구현은 Electron 기반 MVP이며 PRD의 Tauri 메모리·설치 용량 목표를 충족했다고 간주하지 않는다.

## 검증

```sh
npm test
npm run test:desktop
```

데스크톱 테스트는 실제 Electron GUI를 실행한다. 디스플레이가 있는 환경에서 실행해야 한다. 테스트마다 임시 사용자 데이터 폴더를 사용하므로 사용자의 저장 위치를 변경하지 않는다. 드래그와 재실행 복원, 저장 파일 손상, 종료 직전 저장, 포인터 캡처 해제를 검사한다. 다중 모니터 좌표는 단위 테스트로, 실행 중 화면 변경은 모의 화면 이벤트로 검증한다.

F03 자동 테스트는 투명 픽셀 판정, 정지한 커서 아래에서의 애니메이션 변화, 드래그·메뉴 중 입력 유지, 재진입과 페이지 재로드를 검사한다. 커서 위치를 모의로 지정하고 실제 Electron 입력 전환 API 호출을 확인한다. macOS 네이티브 마우스 이벤트로 뒤쪽 테스트 창에 클릭이 전달되고, 펫 픽셀에서 클릭·드래그·우클릭이 동작하는 것도 별도로 확인했다. Windows/Linux와 실제 다중 모니터 환경은 아직 검증하지 않았다.

F04 테스트는 펫 클릭 토글, 네이티브 패널 포커스와 텍스트 입력, Esc·닫기 버튼, 재열기 시 메모 유지, 드래그 구분, 빠른 토글, 화면 안 배치·펫 이동 추종, 앱 종료 시 패널 정리를 확인한다. 패널 스크린샷은 `test-results/f04-panel.png`에 저장한다.
